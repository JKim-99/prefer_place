# 취향지도 (가칭)

## 현재 배포 참고 (2026-11-13)

운영 검색은 2026-09-30 공공 상가정보의 지역별 공개 스냅샷을 사용합니다. 선택한 새 장소는 공공 API 단건 조회로 확인하고 저장하며, 자료 기준일 이후 개업·폐업·변경은 검색에 즉시 반영되지 않을 수 있습니다. 전국 스냅샷은 `prefer-place-public-catalog` Pages 프로젝트에 배포하며 `scripts/export_catalog_shards.py`로 비공개 로컬 사용자 기록을 제외한 공공 장소만 내보냅니다. 스냅샷 갱신은 아직 자동화되지 않았습니다. 공공 API 키는 Pages secret으로 관리합니다. 아래의 이전 운영 안내는 작성 당시 상황으로, 현재 상태는 `HARNESS.md`를 먼저 확인하세요.

공식 최신 CSV를 격리된 로컬 D1에 적재하고 `public_catalog_meta.data_version`과 원본 기준일이 일치하는지 확인한 뒤, 비어 있는 디렉터리에 지역별 스냅샷을 만들 수 있습니다.

```sh
python3 scripts/export_catalog_shards.py --db /path/to/catalog.sqlite --output /path/to/empty-output --version YYYYMMDD
```

생성된 `manifest.json`의 기준일·전체 건수·지역 수와 몇 지역의 검색 및 저장을 검증합니다. 배포는 `prefer-place-public-catalog` 프로젝트에 정적 파일만 올려야 합니다. 프로젝트 루트에서 실행하면 앱의 `functions/`가 함께 배포될 수 있으므로, 임시 디렉터리에서 저장소의 Wrangler 실행 파일을 절대 경로로 지정해 `pages deploy /path/to/empty-output --project-name prefer-place-public-catalog --branch main`을 실행합니다. 원본 ZIP·DB·사용자 기록·API 키는 Git이나 공개 스냅샷에 포함하지 않습니다. 새 스냅샷은 CDN 캐시 때문에 반영까지 최대 1시간이 걸릴 수 있습니다.

대한민국 지역을 탐색하고, 내가 좋아한 식당·카페·숙박·미용실 등 장소를 지도와 목록으로 모으는 개인 취향 아카이브입니다. 회원별 저장 기록을 바탕으로 지역에서 사람들이 자주 선택한 장소와 분위기를 요약해 추천하는 것이 장기 목표입니다.

## 목표와 제품 원칙

- **내 장소가 중심**: 장소 저장은 단순 북마크가 아니라 “왜 좋았는지”, “어떤 분위기였는지”를 함께 기록하는 개인 아카이브로 설계합니다.
- **지도와 목록을 동등하게**: 지도에서 공간 관계를 탐색하고, 목록 보기에서는 분류·정렬·필터를 빠르게 이용할 수 있어야 합니다.
- **대한민국 지역 계층**: 시·도 → 시·군·구 → 읍·면·동 순으로 탐색합니다. 예: 충청남도 → 천안시 → 불당동.
- **개인정보 보호**: 개인 저장 장소는 기본 비공개입니다. 추천 통계는 충분한 사용자 수가 모인 뒤 개인을 식별할 수 없는 집계로만 공개합니다.
- **투명한 추천**: 추천 이유(예: “천안시에서 카페를 저장한 회원들이 자주 선택”)를 설명하고, 표본이 부족하면 추천을 단정하지 않습니다.
- **저작권·지도 약관 준수**: 장소 데이터·지도 타일·검색 결과는 공급자 약관과 attribution 요구사항을 확인한 뒤 사용합니다.

## 초기 사용자 흐름

1. 지역을 선택하거나 위치/지역 검색으로 이동합니다.
2. 지도 보기와 목록 보기를 전환합니다.
3. 음식점, 카페, 숙박, 미용실 등 장소 유형과 분위기 태그로 좁혀 봅니다.
4. 장소 상세를 열어 사진/주소/메모/방문 시점/분위기 태그를 확인합니다.
5. 장소를 개인 컬렉션에 저장하고 “좋았던 이유”를 남깁니다.
6. 개인 장소를 비공개로 유지하거나, 사용자가 명시적으로 선택한 컬렉션만 공유합니다.
7. 지역 추천은 익명 집계와 최소 표본 기준을 만족할 때만 노출합니다.

- MVP 제안: 기본은 비공개, 이후 선택적 공유. 공동 편집은 권한과 변경 이력이 준비된 이후 도입합니다.
- 출처: [Google Maps 장소 목록 만들기](https://support.google.com/maps/answer/7280933?hl=ko)

## MVP 범위

### 1단계: 개인 장소 아카이브

- 지역 계층 탐색(시·도 / 시·군·구 / 읍·면·동)
- 지도/목록 전환 및 지역·카테고리·태그 필터
- 장소 저장, 개인 메모, 방문 날짜, 분위기/목적 태그
- 장소 카테고리: 음식점, 카페, 숙박, 미용실, 문화·여가, 기타
- 사용자별 비공개 컬렉션

### 2단계: 지역 취향 인사이트

- 사용자 선택 동의와 익명화 기준 수립
- 지역·카테고리별 저장 횟수 및 분위기 태그 집계
- 최소 사용자 표본을 충족한 지역만 추천 제공
- 개인 데이터로부터 민감한 속성(건강, 종교, 정치 등)을 추론하지 않음

### 첫 화면 가닥

- 상단: 지역 검색 및 위치 선택
- 좌측/상단 필터: 장소 카테고리, 분위기 태그, 저장 여부
- 본문: 지도와 결과 목록을 나란히 배치(모바일은 지도/목록 토글)
- 장소 상세: 대표 정보, 사용자 메모/태그, 내 컬렉션에 저장 버튼
- 지역 인사이트: 개인 목록과 구분된 익명 집계 카드

## 기술 방향

기존 `coffee` 프로젝트에서 다음 패턴을 재사용할 수 있습니다.

- 정적 `public/` HTML/CSS/바닐라 JS 구조
- Cloudflare Pages + Pages Functions + D1(SQLite)
- 회원가입/로그인, HttpOnly 세션, 서버에서 세션 사용자 확인
- 사용자별 데이터 소유권 검사와 D1 migration 방식
- 하트 선호 토글 UX, 모바일 반응형, 이미지 대체 UI
- Node 기본 테스트 러너(`node --test`)와 Wrangler 로컬 개발

반면 다음은 새 프로젝트 요구에 맞춰 별도 설계합니다.

- 커피 메뉴·문의 전용 테이블과 코드, Compose 브랜딩/디자인은 복사하지 않습니다.
- 재사용은 구조/패턴 수준으로 제한합니다: `public/` 정적 파일 분리, 디자인 토큰·접근성·반응형, `node:test` 기반 DOM/API 스텁, Wrangler Pages 개발·배포 스크립트, D1 세션/소유권 보안 원칙.
- 지도 SDK/provider는 비교 후 adapter 인터페이스 뒤에 둡니다. MVP에서 SDK를 아직 고르지 않았다면 지도 영역은 provider-neutral placeholder로 시작합니다.
- 지도 타일 서버를 무단으로 대량 호출하지 않습니다. 공개 OSM 타일은 사용 정책/attribution/캐시 요구를 확인하고 프로토타입 수준에서만 이용합니다.

### 현재 초기 코드 상태

- `public/index.html`: 지역 선택, 카테고리 칩, 장소 텍스트 검색, 지도/목록 전환의 프런트엔드 프로토타입
- `public/assets/css/styles.css`: 새 프로젝트용 디자인 토큰, 반응형 레이아웃, 지도 미리보기와 장소 카드 스타일
- `public/assets/js/app.js`: 지도/목록 뷰 전환, 예시 장소 카테고리와 키워드 필터
- `migrations/0001_initial_place_archive.sql`: 회원 기본 테이블과 한국 행정구역 계층 테이블의 schema 초안
- `tests/site.test.cjs`: 첫 화면 범위 및 가상 장소 예시의 기본 회귀 검사
- 지도 provider, 로그인/API, 실제 장소 검색과 저장 API는 아직 연결하지 않았습니다.

메인 화면에서 시·도와 시·군·구를 목록으로 선택하면 해당 시·도의 행정 경계 중 선택한 지역을 강조합니다. 일반구가 있는 도시는 시 단위로 합쳐 표시하며, 선택은 브라우저의 로컬 저장소에 보관합니다. 위치 추적은 사용하지 않습니다. 경계 데이터의 출처와 라이선스는 `public/assets/data/README.md`를 확인하세요. 데이터 기준일과 최신 행정구역 반영 여부는 추가 확인이 필요합니다. 공공 상가정보로 저장한 장소는 재접속 시에도 마커가 복원됩니다. 이전 카카오 장소 기록은 좌표를 보관하지 않아 카카오맵 링크로만 확인할 수 있습니다.

## 로그인 로컬 실행

회원가입과 로그인은 Cloudflare Pages Functions와 D1이 필요합니다. 정적 파일 서버(예: `python -m http.server`)에서는 인증 API가 실행되지 않습니다. 로컬 환경에서는 `npm ci`, `npx wrangler d1 migrations apply prefer-place --local`, `npm run dev` 순으로 실행한 뒤 `http://127.0.0.1:8788/`에 접속합니다. 로컬 계정과 세션은 로컬 D1에만 저장됩니다.

운영 환경에서 로그인하려면 Cloudflare D1 데이터베이스를 만들고 `wrangler.toml`의 `database_id`를 해당 UUID로 설정한 후, 원격 마이그레이션을 적용하고 Pages Functions와 D1 바인딩을 배포해야 합니다. 현재 연결된 Cloudflare 계정에는 `prefer-place` D1을 새로 생성하고 0001–0009 마이그레이션을 적용했습니다. 데이터베이스에는 아직 사용자·장소 데이터가 없으며 공공 상가정보 카탈로그는 별도로 적재해야 합니다. 배포할 때 `wrangler.toml`의 ID가 `REPLACE_WITH_NEW_D1_DATABASE_ID` 같은 placeholder가 아닌지 먼저 확인하세요. 비밀번호 재설정과 이메일 확인은 아직 지원하지 않습니다.

## 공공 장소 데이터와 자동 갱신

[소상공인시장진흥공단 상가정보 API](https://www.data.go.kr/data/15012005/openapi.do)의 지역별 자료를 서버 검색 인덱스에 유지합니다. 상호 부분 검색과 자동완성을 위해 검색용 DB는 필요하지만 사용자가 파일을 주기적으로 내려받을 필요는 없습니다. 카카오 장소 API는 사용하지 않습니다. 기존 카카오 기록은 삭제하지 않으며 좌표가 없어 카카오맵 링크로만 볼 수 있습니다. 인기 장소는 실제 방문이 아닌 공개 저장 사용자 3명 이상 기준입니다.

공공데이터의 대·중·소분류는 별도 필드로 보존하고 앱에서는 음식점, 카페·디저트, 숙박, 쇼핑, 미용, 의료, 문화, 교육, 기타 9개로 묶어 지도 범례와 마이페이지 필터에 사용합니다. 원천 소분류명은 장소 상세와 검색 결과에 표시됩니다. 범주 분류는 대/중/소분류 이름 규칙 기반이며, 규칙에 해당하지 않는 업종은 기타로 포함됩니다.

로컬에서는 `npx wrangler d1 migrations apply prefer-place --local`을 실행하고 `.dev.vars`에 `PUBLIC_DATA_API_KEY=일반_인증키(Decoding)`을 설정합니다. `npm run dev`로 사이트를 시작한 다음 별도 터미널에서 `npm run sync:local`을 실행하면 이 작업이 유지되는 동안 자동 갱신합니다. 로컬 작업을 종료하거나 컴퓨터를 재시작하면 다시 실행해야 합니다. 로그는 비추적 `.wrangler/catalog-sync.log`에 기록됩니다. 키는 채팅·GitHub·로그에 넣지 않습니다.

서버는 API 기준월을 하루 한 번 확인하고 기준월이 바뀌면 5분마다 1,000건 이하의 한 페이지를 적재합니다. 지역에 속한 모든 페이지와 중복·총 건수를 확인한 뒤에만 빠진 업소를 검색에서 제외하며, 저장 기록은 삭제하지 않습니다. 좌표가 없는 응답은 새 마커를 만들지 않고 기존 기록은 보존합니다. 오류·한도 초과 시 이전 페이지부터 다시 시도합니다. API에서 빈 DB를 처음 채우는 경우 전국을 순차 적재하므로 시간이 걸리며 그동안 일부 지역만 검색될 수 있습니다. 데이터 갱신 속도는 제공기관의 기준월을 따르며 실시간 개업·폐업을 보장하지 않습니다.

공식 [상가정보 CSV](https://www.data.go.kr/data/15083033/fileData.do)로 초기 데이터를 빠르게 채울 수도 있습니다. 실행 중인 로컬 자동 갱신을 중지하고 마이그레이션 후 `python3 scripts/import_public_places.py --zip /path/to/data.zip --db /path/to/local-d1.sqlite --version 20260930`을 실행합니다. SQLite 파일은 `.wrangler/state/v3/d1/miniflare-D1DatabaseObject/` 안의 `metadata.sqlite`가 아닌 파일입니다. 원본 ZIP, 데이터베이스 및 비밀값은 저장소에 추가하지 않습니다.

### 운영 자동 갱신 설정

운영 D1은 연결되어 있지만 장소 데이터는 비어 있고 동기화 Worker는 배포되지 않았습니다. 새 범주를 사용하려면 로컬 또는 원격 D1에 `0010_place_categories.sql`까지 마이그레이션을 적용해야 합니다. 원격 적용 전 백업과 D1 ID를 확인합니다. 동기화 Worker에는 `npx wrangler secret put PUBLIC_DATA_API_KEY --config wrangler.sync.toml`로 비밀을 설정하고 `npx wrangler deploy --config wrangler.sync.toml`로 배포해야 예약 실행이 시작됩니다. Worker 배포·전국 적재는 아직 실행하지 않았습니다. 현재 보유 로컬 D1 파일은 2026-09-30 CSV로 2,753,778행이 적재되어 있으나, 0010 스키마 마이그레이션은 별도의 빈 시험 DB에서 검증했으며 이 대용량 로컬 파일에는 아직 적용하지 않았습니다. 이 파일은 구버전 스키마이며 새 앱과 함께 사용하려면 백업 후 마이그레이션 또는 최신 CSV 재적재가 필요합니다.

전국 약 275만 건을 1,000건씩 5분마다 처리하면 최소 약 10일이 걸립니다. 인덱스와 검증 기록도 D1 읽기·쓰기 사용량에 포함되므로 [Cloudflare D1의 요금과 일일 한도](https://developers.cloudflare.com/d1/platform/pricing/)를 확인하고 운영 배포 전 충분한 용량과 예산을 확보해야 합니다. 무료 한도를 초과하면 해당 계정의 다른 DB 요청에도 영향을 줄 수 있습니다. 로컬에서의 처리 시간과 운영 무료 한도는 다릅니다.

### 계정과 마이페이지

회원가입은 영문·숫자·밑줄 4~30자의 아이디, 닉네임, 이메일, 10자 이상 비밀번호와 선택적 성별을 사용합니다. 아이디 저장은 현재 브라우저에 아이디만 저장합니다. 기존 이메일 계정은 기존 이메일로 로그인한 다음 마이페이지에서 아이디를 설정할 수 있습니다. 마이페이지에서 대표 이미지, 닉네임과 선택적 성별을 수정하고 비밀번호를 변경할 수 있습니다. 비밀번호 변경 시 다른 세션은 종료됩니다. 대표 이미지는 브라우저에서 작은 JPEG로 변환해 D1에 저장합니다.

내 장소는 카테고리별로 볼 수 있으며 각 장소의 공개를 직접 전환합니다. 새 기록은 비공개이며 공개한 기록만 인기 집계와 익명 사용자 탐색에 포함됩니다. 공공 상가정보 기록은 장소명과 업종을 표시합니다. 이전 카카오 기록은 카카오맵 연결로 표시하고 카카오 응답에서 추론했던 카테고리는 기타로 초기화합니다.
